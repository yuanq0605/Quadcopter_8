# 挑战点七：STM32 裸机驱动电调与电机的启动排查

## 1. 挑战目标

使用 STM32F103C8T6 输出 PWM 信号，通过电调驱动无刷电机，解决“编译与烧录成功，但电机不转”的问题，并理解电调上电解锁与单片机程序执行时序之间的关系。

后续目标是：开发板 USB 保持供电，仅连接电调电池时，电机也能自动完成解锁和启动，无需按 RESET。

## 2. 硬件与信号配置

| 项目 | 本次配置 |
| --- | --- |
| 主控 | STM32F103C8T6 |
| 电调 | Hobbywing Skywalker 20A，按 Skywalker V2 说明书核对 |
| 电池 | 3S LiPo，标称 11.1V、2200mAh，满电 12.6V |
| PWM 输出 | TIM2 通道 1，PA0（板上 A0） |
| PWM 周期 | 20ms，即 50Hz |
| 最低油门输出 | 1000μs |
| 本次运行测试输出 | 逐步增加至 1300μs |

接线确认是排查的第一步。电调各细线用途如下：

- 白线：油门信号，连接 PA0。

- 黑线：地线，连接开发板 GND，两者必须共地。

- 红线：BEC 正电源输出。本次开发板由 USB 供电，未将它接入开发板电源。

- 黄线：辅助反向制动／编程用途，不能当成白色油门信号线使用。

  # 具体过程

  利用cubemx设置完stm32的基础文件后generate code（注意如果使用keil的话，要生成mdk代码且是c语言形式，否则无法下载）
  在生成的代码内根据需要配置修改main.c文件

  只需要接白线和黑线，裸机这里使用面包板和杜邦线会好接一点。

  电池的黑红线对应接到电调上就可以 注意不要接反

## 3. 现象与排查过程

### 3.1 有节奏地报警，电机只随声音轻微抖动

最初接通电调电源后，电调持续有节奏地响，电机没有正常旋转。有时能看到电机随着每次声音轻微运动。

这种运动不能作为成功驱动的证据：电调通过电机发声时，本身就可能引起轻微抖动。

排查中先纠正了信号线识别，随后发现面包板没有插好。修复接触后，声音恢复为“三短一长”。这说明接线接触确实是本次问题之一，不能只检查线是否看起来接上。

### 3.2 三短一长，但电机仍然不转

对于本次 3S 电池，正常启动过程中的三声短响表示识别到三节电池，随后一声长响表示电调准备就绪。

准备就绪不等于电机已经收到运行指令。电调在最低油门下完成解锁后，需要收到更大的油门脉宽，电机才会旋转。

本次程序的启动流程是：

```text
单片机启动
  → 输出 1000μs 最低油门，等待 8 秒
  → 每 200ms 增加 10μs，逐渐升至 1300μs
  → 保持约 10 秒
  → 回到 1000μs，并一直保持
```

这一流程只执行一次。它由单片机上电或 RESET 触发，不会因为电调电池重新连接而自动重跑。
PS：遇到某些莫名其妙的问题的时候多按按reset，很多问题是因为代码运行后脉宽过高或有代码内容进行限制导致的。

### 3.3 按 RESET 后，电机成功转动

按下开发板 RESET 后，程序从头执行：先输出最低油门，让电调完成解锁，再逐步提高油门，最终成功驱动电机旋转。

这是本次关键验证：现有主控、PWM 输出、接线、电调和电机组合具备正常驱动能力。此前“不转”不能直接归因于电机损坏。

### 3.4 同样接电调电源，有时急促连续响，有时正常

开发板 USB 一直供电时，断开电调电池不会使单片机复位。即使没有修改代码，两次接电调电池时，单片机也可能处于不同阶段。

如果在程序输出 1300μs 时给电调上电，电调可能因油门不在最低位置而拒绝解锁；等程序回到 1000μs 后再接电，便可能正常出现三短一长。

因此，“硬件和代码没变，但两次上电结果不同”有明确的时序原因。本次应优先检查电调上电瞬间实际收到的油门信号。

## 4. 报警声音的含义（请注意，很重要）

根据 Skywalker V2 官方说明书，持续报警需要按节奏区分：

| 声音 | 对应含义 |
| --- | --- |
| 连续单声短响：嘀、嘀、嘀…… | 上电时油门未到最低位置；在油门校准后，也可能表示校准范围过窄 |
| 带较长间隔的单声：嘀—、嘀—…… | 没有收到油门信号 |
| 上电后两声一组：嘀嘀，嘀嘀…… | 输入电压超出电调允许范围 |
| 本次正常三短一长 | 识别到 3S 电池，随后准备就绪 |

“油门未回到最低”和“校准范围过窄”是同类声音在不同场景下的解释，不能仅凭响声断定两者同时存在。本次电机已经能在 RESET 后正常旋转，更值得关注的是上电时油门状态。

上电瞬间的一小段启动音，也不能直接等同于持续报警。需确认它是否反复响、后面是否出现正常解锁音。

## 5. 同时遇到的下载问题

排查期间出现过 `ST-LINK USB communication error` 和 Flash Download 失败。USB 插着、指示灯亮着，并不能证明调试器与目标芯片之间的通信正常。

工程中曾存在关闭整个 SWJ 接口的设置。改用下面的配置，可关闭 JTAG，同时保留 SWD 下载功能：

```c
__HAL_AFIO_REMAP_SWJ_NOJTAG();
```

恢复下载时曾借助 BOOT0=1 的启动方式。恢复正常运行时，BOOT0 应回到 0，使芯片从用户 Flash 启动。

## 6. 已验证结果与后续方案

已验证的结果：修复接线接触后，电调能够正常解锁；按 RESET 重新执行最低油门与加速流程后，电机能够真实旋转。

尚不能确认的原因：电池此前未充电，电量不足可能影响运行，但没有电压测量结果，不能把此前所有报警归因于电池亏电。

后续自动启动方案：在 USB 持续供电的前提下，新增电调上电检测，让程序在每次检测到电调供电后执行“最低油门等待解锁 → 逐步加速”，检测到断电后恢复最低油门。

已提出的接法是将电调 BEC 红线通过两只 10kΩ 电阻分压后接入空闲 PA1。该方案与代码已经给出，代码通过了编译器语法检查，但截至本次记录，仍在使用原程序，未完成检测接线与实机验证。BEC 5V 不可直接接到 PA1，也不可在未确认供电设计时与 USB 电源直接并联。

## 7. 本次经验

1. 编译和烧录成功，只说明程序构建与写入完成，不代表电调收到正确的信号。
2. 接线排查需要确认线的功能、共地和实际接触，不能只看颜色或插接外观。
3. 电调正常解锁与电机旋转是两个阶段，最低油门用于解锁，提高油门用于运行。
4. 电调重新上电与单片机复位是两件事；USB 持续供电时，单片机程序不会随电调电池重接而重启。
5. 自动启动要围绕电调上电事件设计，不能仅靠一段开机延时程序。

台架测试时拆除螺旋桨，尤其是在测试上电自动启动时。
