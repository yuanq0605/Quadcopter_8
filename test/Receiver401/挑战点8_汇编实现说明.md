## 一、三份汇编、一个上位机

| 文件 | 内容 | 能不能删 |
| :--- | :--- | :--- |
| `start.s` | 栈、中断向量表、`.data` 拷贝、`.bss` 清零、跳 `asm_main` | 不能 |
| `main.s` | 时钟 84MHz、GPIO 复用、**USART6 收 SBUS**、DMA2_Stream1、NVIC、IDLE 中断、主循环解析 | 不能 |
| `debug_uart.s` | **PA2 / USART2 115200 8N1**、40 字节上传帧、心跳帧 —— 纯调试用 | **可以整块剔除** |
| `sbus_viewer.py` | 电脑端上位机：选串口/参数 → 16 通道条形图实时显示 | 可以 |

`main.s`（接收机主体）：

```
asm_main             入口：自检 .data → 按"时钟 → GPIO → DMA → USART → NVIC"顺序初始化 → 死循环
├─ Clock_Init        HSI 16MHz --PLL--> 84MHz（含 Flash 等待周期、VOS）
├─ GPIO_Init         PC7 → AF8(USART6_RX)        ← 只碰 GPIOC，不碰 GPIOA
├─ DMA2_Stream1_Init DMA2 流1 通道5，普通模式，NDTR=25，USART6_DR → rx_buf
├─ USART6_Init       100k / 8E2 / DMAR / IDLEIE / RE
├─ NVIC_Init         使能 IRQ71（USART6）
├─ USART6_IRQHandler 中断：NDTR==0 → 置 frame_ready；否则算残帧并重装
├─ SBUS_Task         主循环：校验头尾 → 解析 → 重新装填
│  └─ SBUS_Unpack    11-bit 位拼接 → channels[16]
└─ Main_Loop         心跳计数 + 预留飞控任务位置

对外共享：EXPORT channels / sbus_flags   （只有 debug_uart.s 会 IMPORT 它们）
```

`debug_uart.s`（可剔除的调试输出）：

```
Debug_UART_Init       PA2 → AF7(USART2_TX) + USART2 115200 8N1（只开发送）
Debug_OnFrame         收到一帧合法 SBUS 时调用：心跳计时清零 + 发 40 字节通道帧
Debug_OnIdle          这一轮没收到数据时调用：计时满约 0.25s 发一帧"无数据"心跳
  ├─ SBUS_SendFrame   组 40 字节帧（帧头/序号/16 通道/标志/校验/帧尾）→ 轮询 TXE 发出
  └─ SBUS_SendNoData  心跳帧：16 通道 = 1024、CH1 递增、flags = 0xF0
```

`main.s` 调用调试模块只有**两处**，都用条件汇编包着：

```asm
                IF      DEBUG_UART <> 0
                BL      Debug_OnFrame
                ENDIF
```

所以 `DEBUG_UART EQU 0` 之后，`main.s` 与 `debug_uart.s` 之间**一个符号引用都不剩**。

## 三、关键数值是怎么算出来的

### 3.1 主频

```
HSI 16MHz ÷ PLLM(16) × PLLN(336) ÷ PLLP(4) = 84MHz
VCO = 16/16 × 336 = 336MHz          （合法区间 192~432MHz，RM0368 P106）
PLLQ = 7 → 336/7 = 48MHz            （USB 时钟，本挑战点不用）
PLLCFGR = 7<<24 | 0<<22 | 01b<<16 | 336<<6 | 16 = 0x07015410
```

APB1 必须 /2（RM0368 P108 Caution：APB1 不得超过 42MHz），所以 **PCLK1 = 42MHz**。

### 3.2 波特率（BRR）—— 两个串口的值不一样，别抄错

**接收口 USART6（挂 APB2，PCLK2 = 84MHz）：**

```
USARTDIV = 84 000 000 / (16 × 100 000) = 52.5
BRR[15:4] = 52 = 0x34
BRR[3:0]  = 0.5 × 16 = 8
BRR = 0x348
```

**发送口 USART2（挂 APB1，PCLK1 = 42MHz）：**

```
USARTDIV = 42 000 000 / (16 × 115 200) = 22.786
BRR[15:4] = 22 = 0x16
BRR[3:0]  = 0.786 × 16 ≈ 13 = 0xD
BRR = 0x16D          (实际 115068bps，误差 +0.06%，可以忽略)
```

> 同一条公式，两个口算出来差一倍——因为一个在 APB2（84MHz）、一个在 APB1（42MHz）。
> 这也是从 USART2 换到 USART6 时最容易忘的一步：**BRR 必须跟着改**。

**顺带纠一个数字**：你文档里写"16MHz 时钟下 BRR 正好是 0x0A"。按同样公式：
`USARTDIV = 16e6/(16×1e5) = 10.0` → `BRR = 10<<4 = 0xA0`。
写成 `0x0A` 等于 `USARTDIV = 0.625`，实际波特率是 1.6Mbps（快 16 倍），一定收不到。
建议核对一下队友那份代码——如果它真的跑通了，说明实际时钟/配置和你以为的不一样。

### 3.3 帧长度与缓冲区

```
一帧 25 字节，8E2 = 1 起始 + 8 数据 + 1 校验 + 2 停止 = 12 位/字节
传输时间 ≈ 25 × 12 / 100 000 = 3.0ms
帧周期（普通模式）≈ 14ms → 约 71 帧/秒
rx_buf = 256 字节 ≈ 256×12/100k ≈ 30ms ≈ 2 帧余量
```

## 四、几个设计点，以及为什么这么写

当前 `main.s` 是 **v2：单缓冲方案**（v1 环形缓冲版本已备份在 `backup/v1_环形缓冲_20261108/`）。

**1）ISR 只回答一个问题：这一波是不是正好 25 个字节？**
```
读 SR → 读 DR（清 IDLE/RXNE/ORE）
→ frame_ready 还是 1？是就退出（主循环还没取走）
→ 读 NDTR：== 0 → 满帧，置 frame_ready；
             != 0 → 残帧，rx_err_cnt++，DMA_Rearm() 重装
```
整个 ISR 不到 20 条指令（不含重装），1μs 以内。

**2）为什么"只收 25 个"就天然不会错位**
DMA 用**普通模式**、`NDTR = 25`：收满 25 个字节后硬件自动把 `EN` 清零并停下（RM0368 **P176**）。
所以 `rx_buf` 永远只会被写 25 个字节，**不可能写越界、也不可能绕回**。
IDLE 中断又是在"总线已经安静一个字节时间"之后才来的，此刻这一波数据早已发完，
于是"NDTR==0"就等价于"整整收到了一帧"。
重装时把 NDTR 写回 25、写指针回到 `buf[0]`，下一波数据必定从第 0 字节开始 —— 天然对齐。

**3）重装 DMA 是这一版的关键动作（`DMA_Rearm`）**
```
EN=0 → 等 EN 真的变 0 → 读 SR+DR 清掉残留字节 → 清 DMA 标志 → NDTR=25 → EN=1
```
- `SxNDTR` 只有在 `EN=0` 时才能写（RM0368 **P191** "protected ... only if EN is '0'"），
  边收边写会被硬件直接忽略，表现为"怎么都不工作"。
- **必须清掉残留字节**：如果上一帧多来了几个字节、或者主循环慢了一拍，RXNE 里还压着数据，
  不清就重装的话，DMA 会立刻把它搬进 `buf[0]`，整帧就错位了。这是单缓冲最容易踩的坑。

**4）主循环：校验头尾 → 解析 → 重装**
DMA 只负责搬字节，判断对错是软件的事：
- `buf[0] != 0x0F` → 这一波根本不是从帧头开始的（干扰/错位），丢弃，`frame_bad_cnt++`；
- `buf[24] != 0x00` → 长度凑够了但内容错位，丢弃；
- 都对 → 位拼接出 16 通道，再打包从 USART2 发出去。
最后**不管对错都要 `DMA_Rearm`**，否则 DMA 就永远停在那里了。

**5）11-bit 拼接用"移位循环"，不展开 16 段**
第 n 通道取 `frame[1+idx]` 起的 3 个字节拼成 24 位，右移 `bit_offset`，再取低 11 位。
3 个字节够用，因为 `bit_offset + 11 ≤ 18 < 24`。CH1 的结果正好就是
`frame[1] | (frame[2]&0x07)<<8`，和你文档的公式对得上。

### 4.1 v1（环形缓冲）和 v2（单缓冲）怎么选

| | v1 环形缓冲 | v2 单缓冲（当前） |
| :--- | :--- | :--- |
| DMA 模式 | 循环模式，NDTR=256 | **普通模式，NDTR=25** |
| 中断里做什么 | 算 `pos/len`，处理回绕 | 只看 `NDTR==0`，几行就完 |
| 主循环做什么 | 从环形区拷到 `frame_buf`，再滑动窗口找帧 | 直接校验头尾，就地解析 |
| 抗错位 | 滑动窗口自动重对齐 | 头尾校验失败就丢，下一帧自动对齐 |
| 主循环卡顿 | 30ms 内不丢帧 | **超过 14ms 就丢一帧** |
| RAM 占用 | 256 + 256 + 64 字节 | **25 + 64 字节** |
| 代码量 | 多两个函数（Ring_Copy / SBUS_Parse） | 少一半 |

结论：**主循环轻、追求简单就用 v2；主循环重、不能丢帧就用 v1。**
两者都已验证可用，切换只改 `main.s`，`start.s` 和上位机都不用动。

## 五、对你原文和评审意见的核对（重要）

评审意见大方向都对，但有 4 处需要修正或补充，其中 2 处会直接导致收不到数据：

| # | 说法 | 结论 | 依据 |
| :-- | :--- | :--- | :--- |
| 1 | "F4 复位后默认 8MHz 内部晶振" | ❌ **错**，是 HSI **16MHz** | RM0368 **P46** 原文；评审这条纠正是对的 |
| 2 | "16MHz 下 BRR 正好 0x0A" | ❌ **错**，应为 **0xA0** | RM0368 **P519** 公式；0x0A → USARTDIV=0.625 → 1.6Mbps |
| 3 | "清 IDLE 可以往 CR1 的 IDLE 位写 1" | ❌ **F4 不成立**。CR1 bit4 是 `IDLEIE`（中断使能），不是标志位；F4 没有 `ICR` 寄存器，只能"读 SR → 读 DR" | RM0368 **P549** 原文 + **P553** CR1 位定义 |
| 4 | "汇编里没有 volatile，编译器可能把读取优化掉" | ⚠️ **理由不成立**：手写汇编没有编译器优化，`LDR` 就是一条真指令。真正要防的是 **ISR 与主循环的竞态**，所以代码里用 `CPSID I / CPSIE I` 做原子快照 | 见 `SBUS_Task` |
| 5 | "DMA 循环模式下 NDTR 减到 0 自动重装" | ✅ 对 | RM0368 **P176** §9.3.8 |
| 6 | "单缓冲会被新数据踩踏，要双缓冲" | ✅ 对，已用"环形缓冲 + 主循环副本"实现 | — |
| 7 | "F401 可超频到 84MHz（正常）或 96MHz（超频）" | ⚠️ 手册的合法上限就是 **84MHz**，96MHz 不在保证范围内 | RM0368 **P106** "not to exceed 84 MHz" |

另外两条**硬件**上的坑，代码解决不了，需要你看板子：

- **SBUS 是反相的**。R8EF 输出的 SBUS 空闲为低电平，直接进 USART 会一直被判成 break/帧错误。你方案里写了"反向器"是对的——F401 的 USART 没有 RX 极性反转位（CR2 里只有同步模式用的 CPOL/CPHA，见 RM0368 **P554**），必须外部加反相电路（三极管/74HC14/光耦均可）。
- **如果你用的是 Nucleo-F401RE**：PA2/PA3 默认通过 SB13/SB14 接到板载 ST-Link 的虚拟串口（UM1724 **P26**）。
  本方案里 PA2 正好要用作数据输出，所以：
  - **想直接用板载 VCP 看数据** → `SB13` 保持 **ON**（PA2 → ST-Link RX），电脑上那个 COM 口就是数据口；
    `SB14` 建议 **OFF**（PA3 → ST-Link TX），免得 ST-Link 的推挽输出干扰 PA3。
  - **想用外置 USB-TTL** → 把 PA2 和 GND 接到模块上即可，SB13/SB14 都断开。
  - SBUS 现在走 **PC7**，和 PA2/PA3 无关，不再有"抢引脚"的问题。

### 7.1 先分清"哪一头"没通（心跳帧）

固件默认**只有在成功解析出一帧 SBUS 之后才会发数据**——没有遥控器信号时串口是完全静默的。
这会让"串口坏了"和"SBUS 没收到"看起来一模一样。

所以 v2 里加了一个诊断用心跳（`main.s` 的 `HB_LOOPS`）：

> 连续约 **0.25 秒**没有解析到有效帧，就主动发一帧特殊数据：
> 16 通道全 = 1024、CH1 放递增数、`flags = 0xF0`（CH17/CH18/丢帧/失控 全置位）。

于是只看上位机就能判断：

| 上位机上看到的现象 | 结论 | 下一步 |
| :--- | :--- | :--- |
| 什么都不显示（帧率 0） | **串口这条路没通** | 查 PA2 接线、共地、SB13、上位机波特率 |
| 每 0.25s 来一帧，通道全 1024、五个灯全亮、CH1 在跳 | 串口通了，**SBUS 那头没数据** | 查 PC7 接线、反相器方向、接收机模式 |
| 通道值跟着摇杆动、帧率 ~71Hz | 正常 | — |
| 帧率很低、`frame_bad_cnt` 涨 | 收到 25 字节但头尾不对 | 波特率偏差 / 反相器边沿太慢 |

调试完不想保留心跳，把 `main.s` 里的 `HB_LOOPS EQU 0x100000` 改成 `0` 即可。

**排错顺序**（`heartbeat` 在涨但 `sbus_ok_cnt` 不动时）：

1. 示波器/逻辑分析仪量 **PC7**：反相后应该是"空闲高、每 14ms 来一串 3ms 的波形"。
   - 一直是低 → 反相器没接对，或接收机还在 PWM 模式（R8EF 要短按两次 ID SET 切到蓝灯 SBUS 模式）。
   - 有波形但 `ok_cnt` 不涨 → 往下看。
2. 读 `RCC_CFGR` 的 SWS[3:2]，必须是 `10`（PLL 已生效）。如果是 `00`，说明 PLL 没锁上（查 PLLCFGR 的 `0x07015410` 写对没有）。
3. 读 `USART6_BRR`，必须是 **`0x348`**（不是原来 USART2 的 `0x1A4`）。
4. 读 `USART6_CR3` bit6、`USART6_CR1` bit4/bit2，必须都是 1；`RCC_APB2ENR` bit5 也必须是 1。
5. 读 `DMA2_S1NDTR`：每来一帧应该从 **25 递减到 0**，主循环处理完后被 `DMA_Rearm` 写回 25。
   **一直停在 25 不动** → DMA 根本没被触发，查 `DMA2_S1CR` 的 EN/CHSEL（必须 101=通道5）和 `USART6_CR3` 的 DMAR；
   **一直是 0** → 收到了但主循环没在重装，查 `frame_ready` 和 `SBUS_Task` 有没有跑。
6. 上位机收不到：先看 `USART2_SR` 的 bit7(TXE) 是否在跳；用示波器量 PA2 应有 115200 的波形。
   如果波形有但软件收不到，多半是上位机波特率/校验/停止位选得和固件不一致（固件是 115200 8N1）。
7. 如果程序停在 `Default_Handler` 的死循环里，说明有个没实现的中断被触发了，看是哪一个（把 `Default_Handler` 改成记录 LR 或对应中断号）。

## 八、Keil 编译 / 链接报错对照

### 8.1 `L6915E: The semihosting __user_initial_stackheap ...`（已修）

完整报错：

```
.\Objects\Receiver401.axf: Error: L6915E: Library reports error: The semihosting
__user_initial_stackheap cannot reliably set up a usable heap region if scatter
loading is in use
```

**原因：入口函数不能叫 `main`，必须叫 `asm_main`。**

这是 ARMCC/armlink 的一个"自作聪明"的行为：**只要映像里存在名为 `main` 的符号，
链接器就会自动加一条对 `__main` 的引用**，把 C 库启动代码整条链拉进来：

```
__main → __rt_entry → __rt_lib_init → sys_stackheap_outer → __user_initial_stackheap
```

而半主机（semihosting）版的 `__user_initial_stackheap` 在 scatter 分散加载模式下
无法确定堆区，于是报 L6915E。

**证据链**（都是实测，不是猜的）：

1. 用 `--verbose` 链接，日志里明明白白写着：

   ```
   Loading object main.o.
                 definition:  main          ← 就是它
   Adding startup reference.
                 reference :  __main        ← 链接器自己加的
   ```

2. 加 `--entry=Reset_Handler` 后**依旧报错**，说明这跟"入口点没指定"无关——
   是"符号名叫 main"触发的。

3. 你那个能编过的 `asmLight` 工程，入口函数叫 **`asm_main`**，map 里搜不到
   `__main` / `__rt_entry` / `__user_initial_stackheap` 任何一个。

4. 把 `main` 改名成 `asm_main` 后，链接立刻通过（退出码 0），
   映像里也再没有任何 C 库符号。

**修法**（`main.s` 与 `start.s` 已经改好）：

```asm
; main.s
                EXPORT  asm_main
asm_main
                BL      Clock_Init
                ...

; start.s
                IMPORT  asm_main
                ...
                LDR     R0, =asm_main
                BX      R0
```

> 工程里同时也设了 `Options → Linker → Misc controls = --entry=Reset_Handler`
> （和你 `asmLight` 一致）。它能让入口点明确，但**它不是这个错误的解药**，
> 真正的解药是改名。这一点很反直觉，写报告时值得单独讲一句。

### 8.2 `A1581W: Added 2 bytes of padding at address 0x3e`（无害）

```
"Code/start.s", line 281: Warning: A1581W: Added 2 bytes of padding at address 0x3e
```

`|.text|` 这个段声明了 `ALIGN=4`（16 字节对齐），而代码正好 0x3E 字节，所以汇编器在末尾
自动补了 2 个字节凑到 0x40。**这 2 字节不参与执行，不影响任何地址**（`Reset_Handler` 不会被挪动）。

为什么不去掉它：如果把 `ALIGN` 降到 1（2 字节对齐），段基址可能落在"半字地址"上，
段内的文字池（literal pool）就会变成非 4 字节对齐，`LDR Rn, =xxx` 在运行时可能触发
UsageFault。**为省一个警告去冒运行期异常的风险不划算**，建议保留。

### 8.3 `L6314W: No section matches pattern *(InRoot$$Sections)`（无害）

```
"Objects/Receiver401.sct", line 8: Warning: L6314W: No section matches pattern *(InRoot$$Sections).
```

`Receiver401.sct` 是 uVision 自动生成的，里面有一行 `*(InRoot$$Sections)`，
这个选择器是给 C 库的"根段"（`__main` 那一套）预留位置的。
纯汇编工程没有 C 库，自然匹配不到东西，所以提示一句。
**这正是"映像里没有 C 库"的证据**，看到它反而说明改对了。

### 8.4 其它可能遇到的

| 报错 | 原因 | 修法 |
| :--- | :--- | :--- |
| `L6200E: Symbol __Vectors multiply defined` | CubeMX 的 `startup_stm32f401xe.s` 还在工程里 | 把它 Remove/Exclude |
| `L6218E: Undefined symbol Image$$RW_IRAM1$$RW$$Base` | 映像里没有任何 `.data` 段（RW 段被链接器当无用段删了），或 scatter 区域名不是 `ER_IROM1`/`RW_IRAM1` | 让 `sbus_magic` 被真正引用一次（本节代码已如此）；区域名不对就改 `start.s` 里那 4 个 `IMPORT` |
| `L6218E: Undefined symbol main` | 有地方还在引用 `main` | 全部改成 `asm_main` |
| 程序停在 `Default_Handler` | 有未实现的中断被触发 | 见第七节第 6 条 |
| Keil 里中文注释乱码 | 文件是 UTF-8，Keil 默认 GB2312 | Edit → Configuration → Encoding → **UTF-8** |

## 九、`.data` 与 `.bss` 的一个隐藏坑（实测发现）

第一次链接出来的 map 里有这么一行：

```
0x20000000   0x00000004   Data   RW    SBUS_INIT
0x20000008   0x00000268   Data   RW    SBUS_RAM      ← 注意是 Data 不是 Zero
0x20000270   0x00000800   Zero   RW    STACK
```

`SBUS_RAM`（rx_buf、frame_buf、channels 那 616 字节）被标成了 **Data RW**，
意思是这 616 个字节的 0 **被实实在在烧进了 Flash**，开机再由 `Copy_Data` 搬到 RAM：
链接输出（Load Region）因此是 **0x7C8 = 1992 字节**，开机要多搬 620 个字节的 0。

原因：**armasm 里 `SPACE` 默认产生"带初值的数据"**，哪怕初值全是 0。
要真正的 `.bss`（ZI，不占 Flash、由启动代码清零），必须在 AREA 里写 `NOINIT`：

```asm
                AREA    SBUS_RAM, NOINIT, READWRITE, ALIGN=3   ; ← NOINIT 是关键
rx_buf          SPACE   256
```

改完之后 map 变成 `Zero RW`，链接输出缩到 **0x55C = 1372 字节**（RO 0x558 + RW 4），
省下 620 字节 Flash；开机由 `Zero_Bss` 清零即可，不需要从 Flash 搬 620 个 0。
ST 官方启动文件里 `AREA STACK, NOINIT, READWRITE` 也是这个道理。

> 你文档里"缓冲区一定要放 .bss"的说法是对的，但**光写 SPACE 不等于进了 .bss**，
> 这一条值得补进报告里。

## 十一、上传协议与上位机（新增）

### 11.1 接线

```
                    ┌──────────────┐
   R8EF 接收机       │   反相器      │        STM32F401
   1 通道(SBUS) ────►│ (三极管/     ├──────► PC7  (USART6_RX, AF8)
   GND ─────────────►│  74HC14/光耦) │
                    └──────────────┘
   
   PA2 (USART2_TX, AF7) ──────► USB-TTL 模块的 RX
   GND ───────────────────────  USB-TTL 的 GND（必须共地）
```

- SBUS 是**反相**电平（空闲为低），必须经过反相器再进 PC7，否则 USART 会一直判成 break。
- **USART6_RX 在 F401 上只有两个可选引脚：`PC7` 和 `PA12`（都是 AF8）**（DS9716 P45 Table 9）。
  本代码配的是 `PC7`。如果你之前的反相器是接在 `PA3`（老方案的 USART2_RX）上的，
  **必须把线挪到 PC7**——USART6 收不了 PA3，这是外设内部固定的，改代码也没用。
- PA2 只发不收，所以 USB-TTL 的 TX 不用接。
- 若用 Nucleo 板载 ST-Link 的虚拟串口：PA2 要经 **SB13** 连到 ST-Link RX（出厂默认是通的），
  这样电脑上出现的那个 COM 口就是数据口（UM1724 **P26**）。

### 11.2 上传帧格式（固定 40 字节）

| 偏移 | 长度 | 内容 | 说明 |
| :--- | :--- | :--- | :--- |
| 0 | 1 | `0xA5` | 帧头 1 |
| 1 | 1 | `0x5A` | 帧头 2 |
| 2 | 1 | `0x01` | 类型：SBUS 通道数据 |
| 3 | 1 | seq | 帧序号 0~255 循环，丢帧时能看出来 |
| 4 | 32 | CH1 ~ CH16 | 每通道 **uint16 小端**，范围 0~2047 |
| 36 | 1 | flags | 原样转发 SBUS 标志字节：bit7 CH17 / bit6 CH18 / bit5 丢帧 / bit4 失控保护 |
| 37 | 1 | `0x00` | 保留 |
| 38 | 1 | sum | byte0~37 累加取低 8 位 |
| 39 | 1 | `0x5C` | 帧尾 |

- 帧率 ≈ 71 Hz（跟着 SBUS 走），40 字节 × 71 ≈ 2.8 KB/s，115200 下只占约 25% 带宽。
- 用二进制而不是文本：解析不会因为一行没读完就错位，而且带校验，串口上偶发误码能被丢掉而不是显示成乱跳的通道值。
- 发送是**轮询 TXE**（`USART2_SR` bit7）：40 字节 @115200 约 3.5ms，占 14ms 周期的 25%。
  想进一步省 CPU，可以改成 DMA 发送（`DMA2 Stream6 Channel4 = USART2_TX`，RM0368 **P171** Table 29）。

### 11.3 上位机 `sbus_viewer.py`

**安装依赖（只需一次）**


**运行**

### 11.4 代码拆分：主体与调试输出彻底分开

从这一版起，汇编代码分成两个文件，**调试功能可以整块摘掉**，接收机主体不受影响：

| | `main.s` | `debug_uart.s` |
| :--- | :--- | :--- |
| 职责 | 收 SBUS、解析 16 通道 | 把通道数据发给电脑 |
| 用到外设 | USART6 / DMA2 / GPIOC / NVIC | **USART2 / GPIOA（仅 PA2）** |
| 共享数据 | `EXPORT channels`、`EXPORT sbus_flags` | `IMPORT` 这两个 |
| 对外的口 | `Debug_OnFrame` / `Debug_OnIdle` 两个调用点 | 提供这两个函数 |

**剔除步骤（两步，建议都做）**

1. 打开 `main.s`，把第 0 节这一行改成 `0`：

   ```asm
   DEBUG_UART      EQU     0        ; 原来是 1
   ```

2. 在 Keil 里右键 `debug_uart.s` → **Remove File from Group**。

做完之后重编译，`BRR=0x16D`、PA2 的 MODER/AFRL、40 字节协议全部消失，PA2 保持复位默认（浮空输入），
固件只做"收 + 解析"，最适合并入飞控主程序。

> **只改 0 而不移除文件**也能跑：调试代码还在 Flash 里，但一个字节都不会执行，
> PA2/USART2 也不会被初始化。反过来只移除文件却不改 0，会报
> `L6218E: Undefined symbol Debug_UART_Init`——因为 `IF` 块还在引用它。

**实测数据（同一份源码，只切开关）**

| 配置 | 映像大小 | 说明 |
| :--- | ---: | :--- |
| `DEBUG_UART=1` + `debug_uart.s` | **1804 字节** | 含 444 字节调试代码（`DEBUG_CODE`） |
| `DEBUG_UART=0`，不含 `debug_uart.s` | **1344 字节** | 省 460 字节 Flash；RAM 也少 0x34 字节 |

两种配置都验证过：`armasm` 0 错误，`armlink` 0 错误，向量表 `IRQ71` 都正确指向 `USART6_IRQHandler`；
剔除版的映像里搜不到任何 `Debug_` 符号。

**以后想加别的调试手段**（比如把通道数据打到 LCD、存进 Flash），也照这个模式：
新建一个 `.s`，`IMPORT channels`，在 `main.s` 里找一个调用点用 `IF` 包住即可，
主体代码始终不用改。
